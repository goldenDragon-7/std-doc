2.1 §1Top-down, not wish-list

method
Don't write bottom-up ('here's what we have, here's what we could add'). Start with the single artifact the reader will look at, then at every layer ask: for this to exist, what must be true the layer below?
The forcing function
The endpoint conscripts every layer beneath it, so you never have to argue for the prerequisites — the top line visibly demands them. The proof of the proposal is the unwind itself.
Two honesty rules
Separate net-new from reuse ruthlessly (trust comes from NOT rebuilding what exists), and name the one unglamorous gotcha out loud as its own layer.
📐

2.1 §2The seven beats

skeleton
The skeleton has a block for each beat.
1. The one-sentence ask
Concrete, human, what-they-get — not 'a system'.
2. The method box
State that the endpoint is the forcing function.
3. Layer 0 — render the endpoint
Show the actual artifact in colour; list its hard properties (each secretly names a prerequisite).
4. The descent
The vertical stack, each layer joined by '↑ cannot … without'; tag every layer net-new or reuse; light the bottom green.
5. The diagrams
One per load-bearing idea (six idioms — see Move 2).
6. Fold it forward
The same chain as a build table, Phase 0…N; call out reuse vs the honest first brick.
7. The calls
End on the 1–3 decisions genuinely the reader's to make; mark them '◀ YOUR CALL'; commit your own lean first, then invite override.
