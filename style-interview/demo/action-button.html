A document that does things

not your grandma's document — this one has buttons that act

Page 1 was about saying something to a page. This one is the flip side: a page can do something. A living document can carry real controls — buttons that run a command, mint a version, copy a block, kick off a build. The text isn't the whole document anymore; the document is a small, safe set of controls — press one and it acts.

That button didn't navigate anywhere or pop an alert. It did work, in place, and reported back. That's the shape of an action button: a control that performs something and shows you the result without leaving the page. In a real living doc the action can reach further — and it's always one of a few honest kinds:

📋
copy
lift a command or block to your clipboard, ready to paste
🔢
mint
stamp a new version — number + timestamp — on the spot
📨
ask
post a structured choice (radio/select) the awareness reads directly
⚙️
run
trigger a real job — a build, a publish — and stream the result back
One line that keeps this honest — it stays a document, not an app. The temptation is to keep bolting on buttons until your doc becomes a control panel: tabs, dashboards, a general-purpose UI for everything. That's a different tool. A living document's actions are bounded by its subject — a doc about a release can run that release; a doc teaching a command can copy that command; a doc posing a decision can take your answer. The button only does the one thing the page is already about. So the doc doesn't become a place you do any work — it becomes a page that can do its own. And because the action lives right where the idea is — no copying steps out to a terminal, no losing your place — you get real efficiency: fewer steps, fewer errors, fewer questions, without ever stopping being a document.
