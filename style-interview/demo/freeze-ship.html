Freeze & ship

turn the conversation into a thing you can hand to anyone

While you're working, a living doc is alive — the 💬 panel listens, comments flow in and replies flow out. But the moment comes when it's done and you want to send it. Freezing is that moment: it bakes the whole page into one self-contained file with nothing left to phone home — no server, no internet, no dependencies. A frozen doc opens by double-click, forever, on a laptop in a cave.

live vs frozen
◉ LIVE

while you build

  • a local server is serving the page
  • the 💬 panel listens; comments land in an inbox
  • it answers and re-renders from the JSON
  • diagrams may render via a helper on the machine
❄ FROZEN

when you ship

  • one HTML file — every asset inlined, every diagram baked to SVG
  • no server, no network, no dependency; opens over file://
  • the comment widget is stripped — it's a finished artifact, not a draft
  • travels as a file or a .zip; identical on every machine
Freeze means frozen. The security gate refuses to ship a "frozen" doc that secretly still reaches out — no external script, no CDN font, no remote image. If a diagram can't be baked to inline SVG, freeze fails loudly rather than shipping something that breaks in the cave. A gift you give away has to work in the recipient's hands, not just yours.
# one command bakes the portable snapshot + a .zip
std-doc freeze source.json published/ --zip
Why freezing is the same thesis: the cheapest doc to receive is one that asks nothing of the receiver — no install, no account, no trust in a server staying up. Freeze collapses "here's how to run my doc" into "here's my doc." Fewer steps, fewer failures, fewer questions — for the person on the other end, who never has to meet your toolchain to read what you made.
